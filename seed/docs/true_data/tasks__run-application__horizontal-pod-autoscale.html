Horizontal Pod Autoscaling

Source: adapted from kubernetes.io — Horizontal Pod Autoscaling.

What it does

A HorizontalPodAutoscaler (HPA) automatically adjusts the number of replicas of a Deployment or StatefulSet to match demand. This is horizontal scaling — deploying more Pods — as opposed to vertical scaling, which would mean giving the existing Pods more CPU/memory. HPA doesn't apply to resources that can't be scaled, such as a DaemonSet.

How the control loop works

The HPA controller runs periodically (every 15 seconds by default), not continuously. Each cycle it:

  1. Reads the current metric value (e.g. average CPU utilization) for the Pods it targets.
  2. Compares it against the target value configured on the HorizontalPodAutoscaler.
  3. Computes a new desired replica count from the ratio between current and desired metric value: desiredReplicas = ceil(currentReplicas × currentMetric / desiredMetric). For example, if current CPU is 200m and the target is 100m, replicas double.
  4. Updates the target resource's replica count accordingly (scales up if load is high, scales back down — never below the configured minimum — if load drops).

Metric sources

HPA can scale on per-Pod resource metrics (CPU, memory — from the Metrics Server), custom metrics, or external metrics. If a container in the Pod doesn't have a resource request set for the metric being used, that Pod's utilization is undefined and the autoscaler won't act on it — this is why HPA on CPU requires a CPU request to be set.
