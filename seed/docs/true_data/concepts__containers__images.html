Image pull policy

imagePullPolicy controls when the kubelet pulls a container's image:

  • IfNotPresent — pull only if the image isn't already present on the node.
  • Always — always pull the image, even if a copy already exists locally.
  • Never — never pull; the image must already exist on the node.

Naming images correctly

For a private registry, include the registry hostname in the image name, e.g. my-registry.example/my-image:1.2. Always specify a tag or digest — relying on :latest in production makes it unclear which version is actually running, and makes pull failures harder to diagnose.

Private registry authentication

To pull from a private registry, a Pod needs credentials. The usual approaches are: attaching an imagePullSecrets entry to the Pod spec, configuring the node itself to authenticate to the registry, or using a kubelet credential provider that supplies short-lived credentials automatically. A Secret holding registry credentials is typically created with kubectl create secret docker-registry.

ErrImagePull / ImagePullBackOff

If the kubelet can't pull an image, the Pod shows ErrImagePull and then backs off into ImagePullBackOff. The most common causes are: a misspelled image name, a tag that doesn't exist in the registry, or missing/incorrect credentials for a private registry. kubectl describe pod shows the exact error message returned by the registry in its events section.
